# راه‌اندازی پایگاه داده

هم‌پژوه از PostgreSQL و Drizzle ORM استفاده می‌کند. اطلاعات ورود با Better Auth مدیریت می‌شود و داده‌های دامنه در جدول‌های PostgreSQL نگهداری می‌شوند.

## آماده‌سازی محیط توسعه

۱. یک PostgreSQL نسخه ۱۵ یا بالاتر راه‌اندازی کنید.
۲. فایل `.env.example` را به `.env` کپی کنید.
۳. `DATABASE_URL` را به رشته اتصال پایگاه داده خود تغییر دهید.
۴. برای `BETTER_AUTH_SECRET` یک مقدار تصادفی اختصاصی با دست‌کم ۳۲ نویسه بسازید.
۵. فرمان‌های زیر را اجرا کنید:

```powershell
npm install
npm run db:migrate
npm run db:seed
npm run dev
```

## متغیرهای محیطی

- `DATABASE_URL`: رشته اتصال PostgreSQL
- `BETTER_AUTH_SECRET`: راز اختصاصی نشست‌ها و توکن‌های احراز هویت
- `BETTER_AUTH_URL`: نشانی اصلی API احراز هویت
- `APP_URL`: مبدأ مجاز برنامه

فایل `.env` و اسرار واقعی نباید به Git ارسال شوند.

## بررسی خودکار

GitHub Actions یک PostgreSQL موقت اجرا می‌کند، مهاجرت‌ها و داده‌های پایه را اعمال می‌کند، TypeScript و Build را بررسی می‌کند و آزمون API را اجرا می‌کند. آزمون API موارد ثبت‌نام، ایجاد پروژه، خصوصی‌بودن پروژه و درخواست همکاری را بررسی می‌کند.

## وضعیت و محدودیت‌ها

- اجرای CI روی پایگاه داده موقت، جایگزین اتصال پایگاه داده دائمی محیط استقرار نیست.
- جدول فایل‌ها فعلاً فراداده و کلید ذخیره‌سازی را نگه می‌دارد؛ بارگذاری فایل باینری هنوز پیاده‌سازی نشده است.
- جدول project_task وظایف تیم را با وضعیت، اولویت، مسئول، مهلت و زمان تکمیل نگه می‌دارد. گردش کار شامل ارسال برای بررسی، درخواست اصلاح و تأیید نهایی است. ارسال‌کننده نمی‌تواند همان مرحله را تأیید کند؛ نتیجه بررسی، زمان، مدیر بررسی‌کننده و یادداشت او ثبت می‌شود. فقط اعضای پروژه تابلوی وظایف را می‌بینند؛ مشاهده‌گران فقط‌خواندنی هستند و مشارکت‌کنندگان فقط وظایف مرتبط با خود را پیش می‌برند. تأیید داخلی، داوری یا اعتبارسنجی علمی مستقل محسوب نمی‌شود.
- تأیید ایمیل و بازیابی گذرواژه تا زمان انتخاب سرویس ایمیل فعال نیستند.
- جدول‌های `project_discussion_topic` و `project_discussion_post` موضوع‌ها و پاسخ‌های تیم را نگه می‌دارند؛ موضوع می‌تواند به یک وظیفه پیوند بخورد و وضعیت باز/حل‌شده داشته باشد. اعضا می‌توانند بحث بسازند و پاسخ دهند؛ مشاهده‌گران فقط می‌خوانند. بازبینی همتا در این نسخه سازوکار ثبت بازخورد است و تأیید علمی رسمی محسوب نمی‌شود.
- جدول `notification` اعلان‌های شخصی را با فرستنده، پروژه، پیوند داخلی، زمان ایجاد و زمان خواندن نگه می‌دارد. هر کاربر فقط اعلان‌های خودش را می‌بیند و می‌تواند یک اعلان یا همه اعلان‌ها را خوانده علامت‌گذاری کند. رابط اعلان‌ها برای حساب واردشده هر ۳۰ ثانیه به‌روزرسانی می‌شود. ارسال ایمیل و پیام‌رسانی زنده هنوز به سرویس‌های جداگانه نیاز دارد.
- اجرای کد یا فایل‌های ناشناس در سرور هم‌پژوه فعال نیست.

## فراداده مجموعه‌داده‌های پژوهشی

جدول `project_dataset` فراداده مجموعه‌داده‌های وابسته به پروژه را نگه می‌دارد: قالب، مجوز، DOI، تعداد رکورد، متغیرها، روش‌شناسی و ارجاع منبع. خواندن و ثبت این اطلاعات فقط برای اعضای فعال پروژه مجاز است. این قابلیت فایل داده را بارگذاری یا ذخیره نمی‌کند؛ فایل‌های باینری در مرحله ذخیره‌سازی شیءگرا اضافه خواهند شد.

## مهارت‌های پروفایل

مهارت‌های پژوهشگر در جدول مستقل `profile_skill` با ترتیب نمایش و کلید نرمال‌شده ذخیره می‌شوند. شناسه کاربر به پروفایل وابسته است و با حذف پروفایل، مهارت‌ها نیز حذف می‌شوند. مقدارهای تکراری با نرمال‌سازی Unicode و حروف بزرگ/کوچک ادغام می‌شوند.


## دفتر آزمایش و پروتکل پژوهش

جدول `project_experiment` رکوردهای ساخت‌یافته آزمایش‌های پروژه را نگه می‌دارد: هدف، فرضیه، پروتکل، مواد و تجهیزات، متغیرها، شرایط کنترل، مراحل اجرا، مشاهدات، نتیجه‌گیری و وضعیت. هر رکورد به پروژه و ثبت‌کننده وابسته است و می‌تواند به یک مجموعه‌داده همان پروژه پیوند بخورد؛ با حذف مجموعه‌داده، پیوند خالی می‌شود و خود رکورد آزمایش باقی می‌ماند. فقط اعضای فعال پروژه مجاز به مشاهده‌اند؛ نقش مشاهده‌گر فقط‌خواندنی است و ثبت و ویرایش رکورد برای نقش‌های مالک، مدیر و مشارکت‌کننده مجاز است. ویرایش از مسیر مستقل `/api/projects/{projectId}/experiments/{experimentId}` انجام می‌شود؛ تغییرات با شرط `updatedAt` برای جلوگیری از بازنویسی بی‌صدای ویرایش هم‌زمان محافظت و در تاریخچه فعالیت پروژه ثبت می‌شوند. ثبت پروتکل و نتیجه، جایگزین بازبینی یا اعتبارسنجی علمی مستقل نیست.
